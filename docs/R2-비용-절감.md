# R2 스토리지 비용 절감 가이드

`golf-pt-videos` 버킷이 20,000객체 · 500GB까지 커진 원인 진단과 조치 방법입니다.
(R2 요금: 저장 $0.015/GB·월, 쓰기 Class A $4.5/백만, 읽기 Class B $0.36/백만, **송신 무료**)

## 진단 요약 — 500GB는 "쓰레기"가 아니라 "구조적으로 부풀려진 실데이터"

| 원인 | 비중(추정) | 성격 |
|---|---|---|
| **1. mkv 원본 + mp4 변환본 이중 저장** | ~250–300GB | 같은 스윙을 2벌 보관 (mkv는 iOS 재생 불가, 다운로드용일 뿐) |
| **2. 연습샷 전량 영구 보관 (큐레이션·TTL 없음)** | mp4의 대부분 (~150GB) | 모든 볼을 영원히 저장 |
| **3. 삭제 시 mp4/영상 고아** | 수십 GB, 증가 중 | 삭제해도 R2 객체가 남던 버그 |
| **4. 수동 첨부 무압축·무중복제거** | 수십 GB | 폰 원본(15–40Mbps) 그대로 업로드 |
| **5. rec/ 음성 백업 누적** | <0.1GB | STT 실패분 백업이 안 지워짐 |

## 이미 코드로 고친 것 (v9.10 — 앱/워커/에이전트에 반영, 앞으로 발생 방지)

- **삭제 시 mkv+mp4 둘 다 제거**: 샷 삭제·베이 정리·회원 삭제 등 모든 경로에서 `r2RemoveShotVideos()`로 원본·변환본을 함께 삭제. `deleteShot`은 그동안 "영상도 삭제됩니다"라고 안내만 하고 실제로 안 지웠는데 이제 지웁니다.
- **에이전트 이중 저장 중단**: mp4 변환 성공 시 용량 2배인 mkv 원본을 즉시 삭제 → 앞으로 신규 스윙은 mp4 1벌만 저장(약 절반).
- **관리자 스토리지 진단·정리 도구**: 마이페이지 → `🧹 스토리지 진단·정리`.

## 지금 바로 해야 할 것 (순서대로)

### 1단계 — 워커/에이전트 재배포 (코드 반영에 필수)
GitHub Pages는 앱(js/…)만 배포합니다. **워커와 에이전트는 수동 재배포**가 필요합니다.

- **워커**: `worker/golf-pt-storage-worker.js` 최신본 전체를 복사 → Cloudflare 대시보드 → Workers → `golf-pt-storage` → Edit code → 붙여넣기 → **Deploy**. (새 `/__list` 라우트가 있어야 진단 도구가 동작)
- **에이전트**: 스튜디오 Windows PC의 `agent/agent.js`를 최신본으로 교체 → 에이전트 재시작. (mkv 자동 삭제 반영)

### 2단계 — 라이프사이클 규칙 추가 (대시보드, 무료·무위험)
R2 → `golf-pt-videos` → **Settings → Object lifecycle rules → Add rule** 로 아래 2개 추가:

1. **미완료 멀티파트 업로드 정리** — Abort incomplete multipart uploads: **7일**. (외부 도구가 남긴 보이지 않는 조각이 저장비로 청구되는 것을 차단하는 무료 보험)
2. **오래된 음성 백업 만료** — Prefix `rec/`, Delete objects: **30일**.

> ⚠️ R2 라이프사이클은 **접두사(prefix)만** 필터할 수 있고 `*.mkv` 같은 확장자 필터는 없습니다. 그래서 mkv 중복 정리는 라이프사이클로 못 하고 아래 진단 도구로 합니다.

### 3단계 — 중복 mkv 원본 정리 (앱 안, 안전, 최대 절감)
관리자 로그인 → 마이페이지 → **🧹 스토리지 진단·정리**.

- 버킷 구성(mkv/mp4/rec/수동 첨부별 용량·개수)이 표로 나옵니다. **여기서 mkv vs mp4 비중을 보면 이중 저장이 실제로 얼마인지** 바로 확인됩니다.
- `✅ 안전하게 정리 가능` 항목 = **mp4 재생본이 이미 있는 mkv 원본**. 삭제해도 mp4는 그대로라 재생에 전혀 영향이 없습니다. 버튼 한 번으로 정리(수백 GB 회수 가능).
- 삭제 후 대시보드 용량 반영에는 몇 분~시간이 걸릴 수 있습니다.

### 4단계 — DB에서 사라진 회원/세션의 고아 영상 정리 (신중, 별도 진행)
과거 버전에서 회원/샷을 삭제했을 때 R2 객체가 남은 "고아"가 있을 수 있습니다. 이건 **Supabase에 참조가 남아있는지 대조**해야 안전하게 지울 수 있어, 자동 버튼 대신 아래 절차로 진행합니다(요청 주시면 스크립트를 만들어 드립니다):

1. 워커 `/__list`로 전체 키 목록 확보.
2. Supabase의 참조 키 집합 구성: `sessions.media[].r2Key`, `shot_events.video_r2_key`, `shot_events.data.videoMp4R2Key`.
3. **고아 = 참조 집합에 없고 + 생성 24시간 경과** 인 것만 후보. (업로드 진행 중 파일 오삭제 방지)
4. **먼저 리포트만** 출력해 용량·샘플키 확인 → 승인 후에만 삭제.

## 앞으로 검토할 것 (제품 정책)
- **연습샷 큐레이션 + TTL**: 핀 안 한 연습 영상은 30–90일 후 자동 만료. 실사용 영상을 지우므로 보관 정책 결정이 먼저입니다.
- **Cloudflare Stream 전환**: 자동 트랜스코딩·적응형 비트레이트로 저장·재생 최적화(B2B 확장 시 권장).
- **수동 첨부 클라이언트 압축**: 720p·2.5Mbps 재인코딩(iOS는 MediaRecorder 제약으로 효과 제한적).
