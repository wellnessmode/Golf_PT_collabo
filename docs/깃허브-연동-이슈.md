### 함정: 메시지가 원인을 잘못 가리킨다

메시지는 "**조직(organization)** 권한 / 앱 설치 문제"처럼 읽히지만, 실제 원인은
**연결된 깃허브 계정 자체가 다른 계정으로 바뀐 것**이었다. 조직도 아니고 앱 설치 문제도 아니었다.
그래서 "앱 재설치"만 반복하면 절대 안 풀린다.

### 또 하나의 함정: 읽기는 계속 된다

`git fetch` / `git ls-remote` / 파일 읽기는 **정상 동작**했다. 쓰기(push)만 403.
"연결은 살아 있는데 일시적 오류인가?"로 오판하기 쉽다 — 실제로 3시간 헛 재시도했다.

## 진단 절차 (순서대로, 3분이면 끝)

### 1. 프록시부터 배제

```bash
curl -sS "$HTTPS_PROXY/__agentproxy/status"
```

`"recentRelayFailures": []` 이고 `enabled: true` 면 네트워크·프록시는 정상.
→ 문제는 깃허브 쪽이다.

### 2. 읽기 / 쓰기 분리 확인

```bash
git ls-remote origin -h refs/heads/main   # 읽기
git push --dry-run origin <branch>        # 쓰기
```

**읽기 OK + 쓰기 403 = 권한/계정 문제** (네트워크 문제 아님).

### 3. ★ 지금 어떤 계정으로 붙어 있는지 확인 ★ — 결정적 단서

```bash
curl -sS -H "Accept: application/vnd.github+json" https://api.github.com/user
```

```json
{ "login": "brave8hs", "id": 318087918, ... }   ← 저장소 소유자와 다르면 이게 원인
```

> 토큰은 로컬에 없다(`GH_TOKEN=proxy-injected`). 프록시가 주입하므로
> 위 curl 이 그대로 **현재 연결된 계정**을 보여준다.

### 4. 그 계정이 접근 가능한 저장소 목록

`list_repos` 도구(또는 `GET /user/repos`)로 확인. 작업 대상 저장소가 목록에 없으면 확정.

```
brave8hs/idea-validator   (private, can_push: true)
← wellnessmode/Golf_PT_collabo 은 아예 없음
```

## 해결

claude.ai 설정에서 **원하는 계정으로** 깃허브 재연결:
<https://claude.ai/customize/connectors?auth_start=github&auth_start_force=1>

### 재연결 시 주의 (실제로 걸린 것들)

1. **브라우저 로그인 상태를 먼저 정리한다.**
   깃허브에 A 계정으로 로그인된 상태로 재연결하면 **또 A 계정으로 붙는다.**
   → 깃허브 로그아웃 후 진행하거나 시크릿 창에서 원하는 계정으로 로그인.
2. **저장소 선택 화면에서 대상 저장소가 체크됐는지 확인.**
3. **재연결하면 진행 중이던 세션의 깃허브 도구가 죽는다.**
   `Error POSTing to endpoint: invalid session` — MCP 세션이 끊긴다.
   → 새 세션을 시작하거나, 아래 REST 우회로 계속 진행.

## 우회: 도구가 죽었을 때 REST API 로 계속하기

프록시가 인증을 주입하므로 `curl` 만으로 PR 생성·머지가 된다 (토큰 불필요).

```bash
# PR 생성 (draft 아님 — 이유는 아래)
curl -sS -X POST -H "Accept: application/vnd.github+json" \
  -H "Content-Type: application/json" \
  -d '{"title":"...","head":"my-branch","base":"main","draft":false,"body":"..."}' \
  https://api.github.com/repos/<owner>/<repo>/pulls

# 스쿼시 머지
curl -sS -X PUT -H "Accept: application/vnd.github+json" \
  -H "Content-Type: application/json" -d '{"merge_method":"squash"}' \
  https://api.github.com/repos/<owner>/<repo>/pulls/<번호>/merge

# 배포(Actions) 결과 확인
curl -sS "https://api.github.com/repos/<owner>/<repo>/actions/workflows/<파일>.yml/runs?per_page=1"
```

⚠️ **draft PR 은 REST 로 ready 전환이 안 된다.** draft→ready 는 GraphQL 전용인데
이 환경에서는 GraphQL 이 차단되어 있다(`This GraphQL query is not enabled for this session`).
→ 도구 없이 진행할 땐 **처음부터 `draft:false`** 로 만들 것.
(이미 draft 로 만들었다면 닫고 non-draft 로 새로 생성.)

## 두 프로젝트를 같이 쓰려면 — 선택지 비교

전제: 저장소 A = `wellnessmode/Golf_PT_collabo`, 저장소 B = `brave8hs/idea-validator`

| 방식 | 하는 일 | 장점 | 단점 |
|---|---|---|---|
| **A. 협업자 초대** *(권장)* | A 저장소에 B 계정을 Write 협업자로 추가 | 초대 한 번. 재연결 불필요. **주소 안 바뀜** | 두 계정 소유 관계는 그대로 |
| **B. 반대 방향 초대** | B 저장소에 A 계정을 Write 협업자로 추가 + A 계정으로 재연결 | 주소 안 바뀜 | 재연결 단계 추가 |
| **C. 저장소 이전** | A 저장소를 B 계정으로 transfer | 계정 정리됨 | ❌ **Pages 주소가 바뀐다** — 아래 참고 |
| **D. 분리 유지** | 필요할 때마다 연결 계정 전환 | 계정 완전 분리 | 전환할 때마다 반대쪽 저장소가 막힘 |

### C(저장소 이전)를 권하지 않는 이유

커스텀 도메인이 없는 GitHub Pages 프로젝트는 주소가
`https://<계정>.github.io/<저장소>/` 형태다. 소유자가 바뀌면 **주소가 바뀐다.**

골프 앱 기준으로 깨지는 것들:

- 회원에게 이미 보낸 **고정 리포트 링크**
- 프로 폰에 설치된 **PWA** (재설치 필요 + 기기 저장 데이터 초기화 — origin 이 바뀌므로 `localStorage` 리셋)
- 워커에 하드코딩된 리포트 주소, 매뉴얼·문서의 주소

> 참고: 용량 때문에 옮길 일은 없다. 깃허브 개인 계정은 **저장소 개수 제한이 없고**,
> 이 저장소는 전체 2.5MB(.git 6MB)에 불과하다. 저장소당 용량 권고는 5GB 수준.
> **커스텀 도메인(CNAME)을 쓰고 있다면** 이전해도 주소가 유지되므로 C 의 위험이 크게 줄어든다.

## 새 프로젝트 세션에서 미리 확인할 체크리스트

- [ ] 이 세션이 **어떤 깃허브 계정**으로 붙어 있나? → `curl https://api.github.com/user`
- [ ] 그 계정이 **작업 대상 저장소에 쓰기 권한**이 있나? → `list_repos` / `git push --dry-run`
- [ ] 다른 프로젝트도 같은 세션에서 만질 계획인가? → 그렇다면 **한 계정이 두 저장소를 다 볼 수 있게** (협업자 초대) 미리 세팅
- [ ] 재연결이 필요하면 → **깃허브 로그아웃 후** 진행, 저장소 선택 화면 확인
- [ ] 배포가 GitHub Pages 라면 → **커스텀 도메인(CNAME)을 먼저 붙여두기**.
      계정을 옮기거나 저장소를 이전해도 주소가 안 바뀌어, 이런 사고의 파급이 사라진다

## 교훈

1. **403 은 재시도로 안 풀린다.** 일시적 오류와 권한 문제를 먼저 구분할 것 —
   읽기가 되는데 쓰기만 막히면 100% 권한/계정 문제다.
2. **에러 메시지의 "organization / 앱 설치" 문구를 곧이곧대로 믿지 말 것.**
   실제 원인은 연결 계정 교체였다.
3. **연결 계정을 먼저 확인**하는 습관 — `api.github.com/user` 한 줄이면 3시간을 아낀다.
4. 커스텀 도메인은 배포 주소를 계정으로부터 독립시켜 준다. 초기에 붙여두는 게 이득이다.
