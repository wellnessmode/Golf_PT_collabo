## ⚠️ 반드시 할 일 — 워커 재배포 1회

`worker/golf-pt-storage-worker.js` 가 갱신되었습니다(`/r/{id}` 라우트 추가).
평소처럼 Cloudflare 대시보드 → Workers → `golf-pt-storage` → 코드에
`worker/golf-pt-storage-worker.js` 전체를 붙여넣고 **Deploy** 하면 끝.
(시크릿은 기존 것 그대로 사용 — 추가 설정 없음)

재배포 전까지는? 앱이 새 링크를 발급해도 워커가 `/r/` 을 모르는 상태라 리포트가 안 열립니다.
재배포 후 발급한 링크부터 정상 동작합니다. 예전에 보낸 `report.html?id=` 링크는 계속 열립니다.

## (선택) 커스텀 도메인 — report.nationalgym.kr

확인 결과 **nationalgym.kr 은 이미 Cloudflare 를 사용 중**입니다(홈페이지 IP 가 Cloudflare 대역).
그래서 네임서버 교체 같은 어려운 단계 없이, 워커를 배포하는 그 대시보드에서 클릭 몇 번이면 끝납니다.

> 선행 조건: 위의 **워커 재배포(v9.49, /r/ 라우트)** 가 먼저 되어 있어야 합니다.

1. https://dash.cloudflare.com 로그인 (워커 붙여넣을 때 쓰는 그 계정)
2. 첫 화면(Account Home)에 **nationalgym.kr** 사이트가 보이는지 확인
   - **보인다** → 같은 계정. 3번으로.
   - **안 보인다** → 도메인이 다른 계정(예: 홈페이지 제작 업체)에서 관리되는 것.
     이 경우 진행하지 말고 상황을 알려주면 그에 맞는 절차(계정 이전 or 업체 협조)를 안내.
3. 왼쪽 메뉴 **Workers & Pages** → **golf-pt-storage** 클릭
4. **Settings** 탭 → **Domains & Routes** → **+ Add** → **Custom domain**
5. `report.nationalgym.kr` 입력 → **Add domain**
   - DNS 레코드와 HTTPS 인증서를 Cloudflare 가 자동 생성 (보통 1~5분)
   - 기존 홈페이지(nationalgym.kr)와 메일에는 아무 영향 없음 — `report.` 하위 주소만 새로 생김
6. 확인: 폰 브라우저에서 `https://report.nationalgym.kr/r/test` 접속
   → "리포트를 찾을 수 없습니다" 안내 화면이 나오면 연결 성공 (워커가 그 주소로 응답한 것)
7. 연결 완료를 알려주면 `config.js` 의 `REPORT_BASE` 를 켜서 배포 →
   이후 [리포트 공유] 링크가 `https://report.nationalgym.kr/r/...` 로 발급됨
   ```js
   REPORT_BASE: 'https://report.nationalgym.kr',
   ```

(만약 2번에서 도메인이 다른 계정에 있다면: 그 계정 관리자가 위 3~5를 대신 해줄 수는 없고 —
커스텀 도메인은 워커와 도메인이 **같은 계정**에 있어야 함 — 도메인을 이 계정으로 옮기는 것이
정석입니다. 옮기는 절차는 별도로 안내.)

## 보안 현황 — 솔직한 정리

**이번에 막힌 것**
- 고객 링크 경로에서 깃허브/계정명 노출 제거
- 고객 페이지에서 Supabase 주소·anon 키·설정 전면 제거 (서버 주입 방식)
- 리포트 ID 추측 공격 차단 (난수 96비트+)

**아직 남아 있는 것 (고객 링크와 무관하게, 관리자 앱 쪽)**
- 저장소가 공개(public)라서 `config.js` 의 anon 키·워커 API 키가 소스에 보입니다.
  anon 키는 원래 공개 전제 키지만, **RLS(행 단위 보안) 정책이 얼마나 조여져 있는지가 실질 보안**입니다.
- 관리자 앱(index.html)도 깃허브 페이지즈 공개 주소에 있습니다 (로그인은 앱 수준).
