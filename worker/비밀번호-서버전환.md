# 로그인 비밀번호 서버 저장 — 한 번만 하면 되는 설정 (v9.97)

**왜:** 지금까지 비밀번호는 각 폰·PC에만 저장돼서, 앱을 지웠다 다시 깔거나 폰을 바꾸면 초기 비밀번호로 돌아갔습니다. 초기 비밀번호도 앱 코드와 매뉴얼에 그대로 적혀 있었습니다.
**이제:** 비밀번호를 Supabase 서버에 **bcrypt 해시**로만 저장합니다. 공개 키로는 비밀번호 표를 읽거나 쓸 수 없고, 확인·변경용 함수 3개만 부를 수 있습니다.

> 앱(v9.97)은 이미 배포돼 있고, **아래 SQL을 실행하기 전까지는 예전과 똑같이** 동작합니다. 실행하는 순간부터 서버 방식으로 바뀝니다.

## 실행 (대표, 1분)

1. [supabase.com](https://supabase.com) 로그인 → 내셔널짐 프로젝트 → 왼쪽 **SQL Editor** → **New query**
2. 깃허브 `worker/supabase_passwords.sql` 전체 복사 → 붙여넣기 → **RUN**
3. 아래에 `Success` 가 나오면 끝입니다. 다시 실행해도 안전합니다(바꾼 비밀번호는 유지).

## 실행 후 직원들이 겪는 일

| 상황 | 어떻게 되나 |
|---|---|
| 아직 초기 비밀번호를 쓰던 직원 | 초기 비밀번호로 들어가면 **"새 비밀번호 정하기"** 창이 뜹니다. 정한 비밀번호가 서버에 저장됩니다. ("나중에"를 누르면 다음 로그인 때 다시 물어봅니다) |
| 자기 폰에서 비밀번호를 바꿔 쓰던 직원 | 그 폰에서 **쓰던 비밀번호 그대로** 들어가면 앱이 자동으로 서버에 옮깁니다. 따로 할 일이 없습니다. |
| 앱을 지웠다 다시 깔았거나 새 폰 | 서버에 저장한 비밀번호로 그대로 들어갑니다. |
| 비밀번호를 잊은 직원 | 대표가 관리자로 로그인 → 마이페이지 **🔑 직원 비밀번호 초기화** → 직원을 고르고 임시 비밀번호를 정해 줍니다. 직원은 임시 비밀번호로 들어가자마자 새 비밀번호를 정합니다. |
| 같은 계정으로 10번 틀림 | 10분 동안 잠깁니다(맞는 비밀번호도 거절). 10분 뒤 다시 하면 됩니다. |
| 인터넷이 끊긴 상태 | 그 기기에서 서버로 한 번이라도 맞게 들어간 계정은 오프라인에서도 들어갑니다(비밀번호를 해시로만 기억). 처음 쓰는 계정은 인터넷이 필요합니다. |

- 초기 비밀번호는 서버에 처음 한 번 들어가는 용도로만 씁니다. 매뉴얼에서는 지웠으니, 직원에게는 대표가 직접 알려 주세요.
- 한 사람이 여러 기기에서 **서로 다른** 비밀번호를 쓰고 있었다면, 먼저 로그인한 기기의 비밀번호가 서버에 올라갑니다. 다른 기기에서는 그 비밀번호로 들어가면 됩니다.
- 생체 로그인(Face ID·지문)과 "이 기기 자동 로그인"은 예전과 같습니다. 각 기기에만 저장되므로 앱을 다시 깔면 다시 등록해야 합니다.

## 확인

실행 후 아무 기기에서나 로그인해 보세요. 초기 비밀번호로 들어가면 "새 비밀번호 정하기" 창이 떠야 합니다. 창이 뜨면 서버 방식이 동작하는 것입니다.

## 다음 단계 (모두 한 번씩 서버로 로그인한 뒤)

앱 코드에 남아 있는 초기 비밀번호(이전용)를 다음 버전에서 지웁니다. 직원 전원이 한 번씩 로그인했으면 Claude에게 "비밀번호 초기값 코드에서 지워 줘"라고 요청하세요.

## 되돌리기 (비상시에만)

SQL Editor에서 `worker/supabase_passwords.sql` 맨 아래 주석의 `drop ...` 다섯 줄을 실행하면, 앱은 예전 방식(기기 저장)으로 돌아갑니다. 이 경우 서버로 옮긴 비밀번호는 사라지고 초기 비밀번호로 돌아가니, 정말 필요할 때만 쓰세요.

## 기술 메모

- 표: `private.app_passwords(key, hash, must_change, failed, locked_until, updated_at)` — `private` 스키마는 API로 노출되지 않습니다. RLS를 켰고 정책은 없습니다.
- 함수(`security definer`, `search_path=''`): `public.pw_login(p_key, p_pw)`, `public.pw_change(p_key, p_old, p_new)`, `public.pw_admin_reset(p_admin_pw, p_target, p_new)`. anon·authenticated에는 이 3개의 EXECUTE만 줍니다.
- 앱: `verifyPassword()`·`pwServer`·`pwCache`(js/app_core.js), `submitPasswordChange()`·`submitPwReset()`(js/app_handlers.js). 함수가 없으면(PGRST202) 예전 로직으로 동작합니다.
- 로그인 비밀번호는 화면에 들어가는 문을 지키는 용도입니다. 회원 데이터 자체의 보호는 `보안_읽기전용_전환가이드.md`(RLS 읽기 전용 + 워커 쓰기)가 담당합니다.
